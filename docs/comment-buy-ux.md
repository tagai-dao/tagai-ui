# 评论买币：账户式交互

## 用户要完成的事

清楚知道钱在哪里、现在能不能买、下一步点什么，以及买入是否成功。首页不展示合约参数表单。

## 信息架构

- AI Au-Pay 内分为「评论买币」「社交打赏」。分别管理资金、合约、授权，默认展示评论买币。
- 买币首页：账户余额与主要操作、三步引导与可复制指令、授权摘要、最近订单。
- 充值和授权合并在同一弹窗；仍提供单独管理额度、提现和关闭授权。手机使用项目既有底部抽屉，确认按钮固定在底部。
- 费用规则和支持范围按需展开；没有隐藏实际费用或默认提高用户授权。
- 用户文案只解释收费、成交保护、使用方式和资金操作，不出现 Keeper、Vault、部署等开发术语。合约入口使用「查看资金合约」，完整地址保留在链接和悬浮提示中；确认弹窗显示短地址，便于核对。

## 主要状态与下一步

| 状态 | 主要操作 |
| --- | --- |
| 非 BSC | 切换 BNB Chain |
| 未登录 X | 登录 X 账号 |
| 未连接正确钱包 | 连接绑定钱包 |
| 余额未充值或不足 | 充值并设置授权 |
| 有资金、未授权或授权已失效 | 设置额度并开启 |
| 旧授权的执行费额度不足 | 更新买币授权 |
| 已开启 | 充值；另外提供管理额度与关闭入口 |
| 服务暂停 | 禁止充值与新增授权；仍保留提现与撤销 |
| API 仍指向旧版分账 Vault | 明确显示旧版账户，只允许提取与撤销，避免对旧合约调用新版 ABI |
| 接口错误 | 提示重试；不将读取失败显示成零余额 |
| 交易已提交、回执未确认 | 保留交易链接和检查结果；不允许重复提交 |

## 金额与授权表达

- 一个买币余额，同时支付买币本金、0.0005 BNB 执行费和实际协议费；页面只填写一个充值金额，不再预存独立手续费。
- 首次充值或修改授权：调用六参数 `authorize(...)` 并携带充值 `value`，一笔链上交易完成。验证 X 钱包仍可能要求一次无 gas 的签名。
- 已有授权默认填写链上的剩余额度、每笔和每日限额；有效期默认「保持原到期时间」，不按剩余天数向上取整延期。
- 保持设置不变时调用 `deposit()`：只增加余额，不重置授权版本、剩余额度、有效期和当日已用额度；用户修改设置时才重新授权。充值额不自动扩大旧额度。
- 授权仅需填写每笔、每日、总额度与有效期；总额度包含费用。不提供费率、滑点或执行费上限输入。
- 当前生产配置：平台比例服务费为 0，成功买入固定收取 0.0005 BNB 执行费（给 Keeper），协议费另计。真实页面从公开 API 读取费用，预览使用对应模拟值。
- 授权确认前只读展示执行费与 5% 滑点。确认时执行费上限设为 API 当前值，滑点设为 500 bps；链上已有授权不会直接改变。旧授权执行费不足时提示重新授权。
- 新合约删除授权接口及 Grant 的 maxPlatformBps，协议费用安全上限由合约常量 MAX_PROTOCOL_FEE_BPS 固定为 300 bps（非实际收费比例），前端不传该参数。旧合约使用独立 ABI 读取授权并仅提供提现/关闭功能。后端滑点最多 5%，也遵守旧授权的更严格限制。
- 保存修改会按填写值设置剩余额度和有效期，不重置当日已用额度。首次默认充值 0.01 BNB，总授权按打开弹窗时的余额加充值额建议；均可自行调整。
- 提现不会自动撤销授权；撤销不会自动提现。这两种操作均需要用户确认。

本地预览使用真实 Vue 组件与隔离数据，不连接真实 API、RPC 或钱包；不会发送链上交易。未新增生产预览路由或测试网部署。

统一余额新版 Vault（`vaultVersion() = 2`）已部署至 `0xA0bd437d2B6edE47104d194EE18048d5fc78dc5E`；Adapter 不变。API 无需新接口，只需与 Keeper 同步 `COMMENT_BUY_VAULT`，前端从 API 读取地址。旧余额、授权不会自动迁移。切换 API 地址前安排旧资金提取和旧授权撤销，并处理旧合约的未确认订单。
