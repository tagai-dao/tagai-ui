# BSC V13 本地人工验收环境

本模式启动 **现有 tiptag-ui 页面**，临时替换 RPC、钱包桥接和必要 API。
不是另一套交易界面，也不会自动替用户完成页面操作。后续交互改进直接修改原 `src/` 页面，可正常用于生产。
正式 API、索引、server 无需运行或修改。

## 启动

依赖：已安装 Foundry/Anvil、前端 npm 依赖，以及同工作区 tagai-api 的 ethers v6 依赖。
只读取合约仓库 `.env` 中的 `BSC_RPC_URL`（也可在启动环境指定同名变量）；不读取或使用主网私钥签名。

```bash
cd "/Volumes/Extreme Pro/wangxi/work/tiptag/tiptag-ui"
npm run dev:fork
```

打开 **http://127.0.0.1:15173/bsc**，使用装有钱包扩展的浏览器。

| 服务 | 本地地址 |
| --- | --- |
| 原前端 + 本地管理面板 | http://127.0.0.1:15173 |
| 临时 API | http://127.0.0.1:19900 |
| 本地 RPC 调度入口 | http://127.0.0.1:18545 |
| Anvil 内部端口（不要配置给钱包） | http://127.0.0.1:18546 |
| 钱包添加网络的 RPC | http://localhost:18545 |
| 钱包链 ID | **560013** |

首次启动从当时的 BSC 链头创建 fork；存在 `.local-fork/checkpoint.json` 时，正常启动默认恢复快照对应的链和社区。需要全新环境时运行 `npm run dev:fork -- --fresh`，旧数据会先归档。后续主网新区块不会同步到已启动的 fork。
本地执行使用合约编译目标 Cancun，每 2 秒出块以保持报价 deadline 的链上时间新鲜；也可使用管理面板快进时间或区块。Cancun 避免 Anvil 默认新版硬分叉的历史存储更新不断触发上游读取和限流。
界面业务链仍为 BSC/56，钱包签名及本地 EVM 使用独立 ID 560013。
本地配置同时适配了路由 hash 中的 chainId；不能只改 RPC 而保留主网签名目标。

## 人工操作顺序

1. 在橙色管理面板点击「连接 / 添加本地链」，由钱包确认添加和切链。使用浏览器钱包，不需要真实社交登录。
2. 点击「补到 1000 BNB」，给当前钱包分配测试 BNB。
3. 点击「创建代币（原页面）」打开原创建弹窗，选择成分和参数并在钱包确认。本地测试不强制上传 Logo，未上传时使用默认测试图片；正式页面仍要求上传。
4. 新社区出现在管理面板和原列表中。点击社区进入原详情/交易页；临时 API 从创建回执入库，无需等待 Graph。
5. 正常购买代币直到 pendinglist。需要跳过创建保护时间时，先快进 20 秒。
6. 默认自动 keeper 关闭，方便观察等待上市页面。点击该社区的「List」或「Keeper 执行一次」完成上市；也可开启每 5 秒扫描的自动 keeper。
7. 在原页面测试主池/多池买卖、BNB 加池和双资产加减流动性。在玩法 Tab 授权并质押 LP。
8. 快进 3600–7200 秒，再做一笔买入触发 Hook 的周期奖励注入。注入按后续整点、168 小时线性释放，所以再快进至少 3600 秒后查看待领取奖励，领取、解押并移除流动性。

钱包和本地 RPC 的链 ID、区块 hash 都会核对；钱包若已有同 ID 但不同 RPC 的网络，需将它的 RPC 改成上表地址。
连接默认优先使用 EIP-6963 公告的 MetaMask（`io.metamask`），避免多个扩展抢占 `window.ethereum`；管理面板显示实际选中的钱包名称。
若旧版 MetaMask 仍以 HTTPS 校验错误拒绝自动添加，在钱包的网络设置中手动添加 `BSC Local Fork`：RPC 为 `http://localhost:18545`、链 ID `560013`、货币符号 `tBNB`，然后回页面重新连接。`localhost` 和 `127.0.0.1` 都指向同一个本地节点，不需要改成公网 RPC。
管理面板可收起，不改变原页面布局和操作方式。当前没有真实 Twitter、Privy 登录或外部社交动作。

## 管理操作

- **移除记录**：仅移除选定社区的临时数据；已发生的链上交易不回滚。
- **清空临时数据**：清空社区、keeper 记录及当前站点测试缓存，保留链上状态。
- **重置 Fork + 数据**：回到本次启动时的链与社区状态；如果本次从检查点恢复，这个起点包含恢复的社区。全新环境使用 `--fresh`。
- **快进并出块**：设置快进秒数与区块数；支持矿池奖励、锁定时间等交互测试。
- **保存链与社区快照**：立即保存检查点。空闲时也会每 30 秒保存；keeper 或其他管理写操作正在执行时会跳过这一轮。
- Ctrl+C 会先尝试保存检查点，再停止本任务的 Anvil、RPC 调度、临时 API 和 Vite，不停止原本运行的 5173 前端或其他服务。

完整重置后钱包可能保留旧 nonce，此时清除钱包中这个本地网络的活动记录再连接。
正常重启恢复最近成功检查点；异常退出时，检查点之后的操作可能丢失。恢复较早检查点后，先核对余额和交易回执，再决定是否重新操作。浏览器刷新不会丢失社区。

## 临时数据和接入范围

`.local-fork/` 保存 JSON 状态、上传图片及日志，已 gitignore。只监听 127.0.0.1。
临时 API 不连接 MySQL、Redis、Graph，也不转发请求到正式 API。

- 创建选项：从本地 Pump/IPShare/Committee 查询真实费用和资产白名单。
- 创建登记：验证本地成功回执，将社区、Token、成分、V2 pair、矿池关联写入 JSON。
- 读取：本地社区列表、搜索、详情、V13 配置、路径/tick 元数据、价格、交易记录、持有人及简单图表数据。
- 本地代币上市后继续使用原 K 线组件和本地成交记录，不查询 DexScreener 中不存在的 fork 代币。
- 钱包/矿池余额、LP 预估、待领取奖励等继续由正式前端逻辑直接查询 fork 合约。
- 买卖路径和 LP 数量由现有 Worker 算法计算；链上执行使用 version13.json 中的已部署交易/流动性合约。
- keeper 使用 fork 内当前 listingKeeper 的 impersonation，不用主网私钥。按成分预算查询实际报价、应用 Pump 的滑点设置，先模拟完整 List，再在本地发送。
- keeper 上市后以有限并发预热路径内 tick 存储，避免第一次前端 Multicall 串行读取数百个远端存储槽。首次上市准备可能需要数分钟，取决于上游 RPC 的速度和限流；前端仍只执行原来的一次快照 Multicall。
- 启动时仅在 fork 内补齐 Basket registrar/forwarder 和矿池工厂的必要权限；不变更线上权限。
- 外围社交 GET 返回空数据；未实现的外围写入返回 501，不伪装成功。页面连接策略禁止向公网 API/RPC 请求。

`vendor/metadata.cjs`、`vendor/creation.cjs` 是对应 API 纯逻辑的本地副本，用于复用回执结构和 tick 发现约定；将来 API 契约变化时按需同步。
`ethers.cjs` 只复用工作区已安装的 ethers v6 包，不启动或加载正式 API 服务。

## 与正式代码的隔离

只有 `dev:fork` 使用 `local-fork/vite.config.ts`。它在开发时替换钱包模块、RPC 配置、Privy 启动、上传地址及路由 hash 的本地 chainId，并注入管理面板。
`npm run dev` / `npm run build` 不加载这些替换。人工验收中完成的交互修正保存在原 `src/` 业务代码，随正式前端一同构建。
因此在用户验收时发现的 UI 问题，应修改 `src/` 的正式组件，而不是另写本地交易页面。
独立缓存放在 `.local-fork/vite-cache`，不与正常 5173 开发服务共享依赖预编译缓存。

## 开发者检查

以下是环境连通性检查，不是用户的测试入口。要求当前会话无社区，结束后重置本地快照：

```bash
node local-fork/check.mjs
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p local-fork/tsconfig.json
```

检查创建、回执登记、内盘到 pending、keeper、Basket/矿池关联、原前端快照/LP 算法、路由 hash、买卖、BNB 加池、质押/奖励/领取/退出和重置。
钱包扩展的实际确认弹窗与最终交互体验由用户在原页面验收。

本地 RPC 查询禁用 ethers JSON-RPC 批处理，避免首次 tick 预加载拖住 status/metadata；上市后的 metadata 缓存 60 秒。创建新的成分组合时，首次读取仍可能较慢，等待预加载完成后再刷新报价。

## RPC 稳定性与恢复

2026-09-09 的故障中，Anvil 连 `eth_chainId` 都不再响应；线程采样显示两个历史存储读取分别阻塞在状态锁和 fork 存储返回上。当前规避措施只用于本地环境：

- `rpc-gateway.mjs` 对存储、余额、代码、nonce 读取及快照操作采用排他调度，其余请求最多并发 8 个。JSON-RPC batch 也逐项经过调度，保留原请求参数和区块，不把历史状态偷换成 latest。
- 上游 fork RPC 单次超时 15 秒、重试参数设为 2；入口超时 90 秒。入口发生传输故障后熔断，返回明确错误，不重发任何交易；每 5 秒探测恢复，只有两次探测间确认区块继续增长且状态读取成功才重新接收普通请求。HTTP 超时无法取消 Anvil 内已经开始的操作，因此不会冒险继续往失去响应的节点堆请求。
- 每 15 秒检查节点响应和出块进展（区块 30 秒未变化也报警），不自动清空或重置链。管理面板读取 12 秒超时且不会重叠轮询。
- 临时 API 空闲时每 30 秒使用 `anvil_dumpState` 保存账户、合约状态、区块和交易，并与社区 JSON 一起原子替换 `.local-fork/checkpoint.json`。保存失败保留上一份；保存不包含全部历史状态 trie，恢复后某些旧区块状态查询可能不可用。
- 重启读取检查点，固定原 fork 来源区块并用 `--load-state` 恢复；自动 keeper 恢复后默认关闭，避免用户还没检查就继续执行。旧版只有 `state.json` 而无链快照且含社区时，默认拒绝覆盖，需显式使用 `--fresh`。

这些措施降低已观察到的并发卡死风险，并提供恢复手段，不保证上游 RPC 或 Anvil 永远无故障。若再次无响应，停止本地服务后运行 `npm run dev:fork` 恢复最近检查点；不要用 `--fresh`，除非确实希望重新创建测试链。

调度回归检查：`node --test local-fork/rpc-gateway.test.mjs`。

第二次异常的修正：区块高度/交易回执等只读查询使用独立的最多 4 并发通道，冷状态调用不会占满回执查询能力；社区实时信息按代币合并并发请求并短暂缓存 1 秒，减少页面、列表和管理面板重复发出的同一组读取。`/health` 显示排队数量、活跃 RPC 方法及耗时。keeper 成功上市后先保存结果并尝试保存链快照，再预热 tick，预热失败不再把已成功的上市显示为交易失败。此次并未升级 Anvil 二进制。

### 多成分报价的 tick 总量

本地 `vendor/metadata.cjs` 的每池 128 条上限，不能保证四成分路由的总量低于前端 512 条限制。`tick-budget.cjs` 在池子去重后分配总额度：稀疏池保留全部 tick，剩余额度均衡分给密集池，并保留当前价格附近的连续 tick 窗口、缩小覆盖边界。全部路由仍参与报价，前端仍只读取一次 aggregate3；超出已提供窗口时不得外推。

回归检查：`node --test local-fork/tick-budget.test.mjs`。这是本地报价服务的修正，尚未同步到独立的 `tagai-api/src/services/v13/metadata.js`。
